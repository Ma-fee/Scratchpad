# Task 24: Complete Whiteout Lifecycle for OverlayFileSystem

## Implementation Summary

This task implements the complete whiteout lifecycle for the OverlayFileSystem, enabling
proper directory removal, recursive deletion, stale whiteout cleanup, and whiteout
verification.

## Files Modified

- `src/mcp_scratchpad/fs/overlay.py` - Main implementation file

## Methods Implemented

### 1. `rmdir(path, **kwargs)` - Remove Directory with Whiteout Support

- Removes empty directories from upper layer directly
- Creates whiteout marker (`.wh.<dirname>`) for lower layer directories
- Raises `OSError` if directory is not empty
- Raises `NotADirectoryError` if path is a file
- Idempotent: succeeds if directory is already whited-out

### 2. Enhanced `rm(path, recursive=False, **kwargs)` - Handle Recursive Directory Deletion

- Added `recursive` parameter (default: False)
- When `recursive=True`: recursively removes directory and all contents
- Handles both upper layer (direct removal) and lower layer (whiteout creation)
- Files are removed or whited-out individually before directory whiteout
- Maintains proper overlay semantics throughout recursive operations

### 3. `clean_whiteout(path=None, expired_only=True, dry_run=False, **kwargs)` - Remove Stale Whiteout Markers

- Removes whiteout markers that are no longer needed
- Stale whiteouts are those where:
  - The hidden file/directory no longer exists in any lower layer, OR
  - A new file/directory with the same name exists in upper layer, OR
  - The whiteout has expired (future: TTL support)
- Parameters:
  - `path`: Directory to clean (default: root "/")
  - `expired_only`: If True, only remove stale whiteouts (default)
  - `dry_run`: If True, report what would be removed without actually removing
- Returns: List of whiteout paths that were (or would be) removed

### 4. `is_whited_out(path, include_expired=False, **kwargs)` - Check if Path is Hidden

- Public API to check if a path has a whiteout marker
- Returns True if whiteout marker exists and is not expired
- Parameters:
  - `include_expired`: If True, return True even for expired whiteouts
- Used by `ls()` and `exists()` to filter/hide whited-out items

### 5. `WhiteoutEntry` Dataclass - Whiteout Expiration Tracking

```python
@dataclass
class WhiteoutEntry:
    path: str                    # The path that is whited out
    whiteout_path: str          # The actual whiteout marker file path
    created_at: float           # Unix timestamp when created
    expires_at: float | None    # Unix timestamp when expires (None = no expiration)
    layer_index: int            # Layer index of hidden file (0=upper, 1+=lower)
```

- Provides structure for whiteout metadata
- Supports future TTL-based whiteout expiration
- Currently unused in core logic but available for future enhancements

## Helper Methods Added

### `._rmdir_recursive_overlay(path, recursive=False, **kwargs)`

- Internal method for recursive directory removal
- Handles both upper and lower layer directories
- Removes contents recursively before directory whiteout

### `._rm_file_with_whiteout(path)`

- Internal helper for file removal with automatic whiteout for lower layers
- Used by recursive directory removal

### `._get_whiteout_paths(dir_path)`

- Returns all whiteout marker paths in a directory
- Used by `clean_whiteout()` for discovering whiteouts

### `._is_whiteout_stale(whiteout_path)`

- Determines if a whiteout marker is stale
- Checks if hidden file still exists or if upper layer now has content

## Integration with Existing Methods

### `ls()` - Updated to Hide Whited-Out Directories

- Now checks if directory has whiteout marker first
- Returns empty list for whited-out directories
- Hides all contents of whited-out directories

### `isdir()` - Updated to Respect Whiteouts

- Returns False if directory has whiteout marker
- Preserves overlay semantics for directory visibility

### `_create_whiteout(path)` - Existing Method

- Creates `.wh.<filename>` marker in upper layer
- Used by `rmdir()` and `rm()` for lower layer items

### `_remove_whiteout(path)` - Existing Method

- Removes whiteout marker if it exists
- Called when creating new files/directories to prevent blocking

## Whiteout Pattern

Whiteout markers follow Docker overlay2 filesystem convention:
- Naming: `.wh.<original_filename>`
- Location: Same directory as original file
- Example: Deleting `/dir/file.txt` creates `/dir/.wh.file.txt`

## Example Usage

```python
# Remove empty directory
overlay.rmdir("/emptydir")

# Remove directory recursively
overlay.rm("/dir", recursive=True)

# Check if path is whited out
if overlay.is_whited_out("/deleted.txt"):
    print("File was deleted")

# Clean stale whiteouts
removed = overlay.clean_whiteout("/", expired_only=True, dry_run=False)
print(f"Removed {len(removed)} stale whiteouts")
```
