### rename() Method Features

#### COW Semantics
- Renaming a file from lower layer triggers COW (copy to upper first)
- Original lower layer file is hidden with a whiteout marker
- Lower layer remains unchanged (preserving immutability)

#### Cross-Directory Support
- Automatically creates parent directories for destination
- Works with deeply nested paths (e.g., `/a/b/c` to `/x/y/z`)

#### Overwrite Behavior
- If target exists in upper layer: removes and replaces
- If target exists in lower layer: creates upper layer copy (overlay semantics)

#### Error Handling
- Raises `FileNotFoundError` if source doesn't exist
- Raises `IsADirectoryError` if source is a directory (not supported)

## Implementation Notes

### Key Design Decisions

1. **COW First**: When renaming lower layer files, we first copy-up to upper layer,
   then move the copied file to destination. This ensures atomic-like semantics.

2. **Whiteout for Lower Layer Sources**: When the source is in lower layer, we create
   a whiteout marker to hide the original file after "moving" it.

3. **Upper Layer Direct Removal**: When source is already in upper layer, we simply
   delete it after copying to destination.

4. **Reuse rm() for Target**: We use the existing `rm()` method to handle target
   removal, which properly handles both upper and lower layer targets with whiteout.

### Whiteout Interaction

During rename from lower layer:
1. File copied to upper layer (COW)
2. File copied from upper source to upper destination
3. Whiteout marker created for original source (hides lower layer file)
4. Copied-up source removed from upper layer

Result: Original lower layer file is hidden, destination has the content.
