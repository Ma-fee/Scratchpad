# Task 38: Large file resource (metadata + preview) - Implementation Evidence

## Summary
Successfully implemented large file handling for MCP resources with metadata-only retrieval and preview mode for files > 1MB.

## Changes Made

### 1. Added Constants (read_handler.py)
- `LARGE_FILE_THRESHOLD = 1024 * 1024` (1MB) - Files larger than this trigger preview mode
- `DEFAULT_PREVIEW_SIZE = 1000` - Default number of bytes/chars in preview chunks

### 2. New Dataclasses (read_handler.py)
- `LargeFilePreview`: Stores preview information for large files including:
  - total_size: File size in bytes
  - mimetype: Detected MIME type
  - preview_start: First N bytes/chars (base64 for binary)
  - preview_end: Last N bytes/chars (base64 for binary)
  - line_count: Number of lines (for text files)
  - is_binary: Whether content is binary
  - message: Human-readable message

- `FileMetadataResult`: Stores metadata-only information:
  - uri, session_id, path
  - exists: Whether file exists
  - size: File size
  - mimetype, modified, created
  - is_binary, is_directory
  - line_count (for text files)

### 3. New Functions (read_handler.py)

#### count_lines_in_text(fs, path, sample_size=1MB)
Efficiently counts lines in text files. For large files, samples beginning to estimate line count without loading entire file.

#### read_large_file_preview(fs, path, mime_type, preview_size)
Reads preview of large file (start and end chunks) without loading entire file into memory.
- For binary files: reads byte chunks and base64 encodes
- For text files: reads text chunks
- Returns LargeFilePreview with preview data

#### get_file_metadata(uri, session_manager, include_line_count=True)
Gets file metadata without reading content.
- Returns FileMetadataResult with size, type, timestamps, line count
- Efficient for checking file info before reading

#### read_file_chunk(uri, offset=0, limit=1024, session_manager)
Reads a specific chunk of a file using offset and limit parameters.
- Supports both text and binary files
- Enables partial file reading for large files

### 4. Modified Functions

#### read_resource() - Enhanced for large files
- Now detects files > LARGE_FILE_THRESHOLD (1MB)
- For large files: returns preview mode with JSON-serialized preview data
- For normal files: returns full content as before
- Prevents memory issues with very large files

## Large File Preview Format

For files > 1MB, read_resource() returns content as a JSON object:

```json
{
  "type": "large_file_preview",
  "total_size": 10000000,
  "mimetype": "text/plain",
  "preview_start": "first 1000 chars or bytes",
  "preview_end": "last 1000 chars or bytes",
  "preview_size": 1000,
  "is_binary": false,
  "line_count": 50000,
  "message": "File too large (10000000 bytes), showing preview of first and last 1000 bytes/chars"
}
```

## Performance Considerations

1. **Memory Efficient**: Large files never fully loaded into memory
2. **Streaming**: Uses cat_file() for byte-range reading when available
3. **Sampling**: Line count uses sampling for very large files
4. **Preview Only**: Returns ~2KB of data per large file instead of potentially GBs

## Example Usage

```python
# Read file (automatically switches to preview for large files)
result = read_resource("scratchpad://session/large.log")
if result.metadata.size > 1024*1024:
    preview = json.loads(result.content.data)
    print(f"File size: {preview['total_size']}")
    print(f"Preview start: {preview['preview_start'][:100]}...")

# Get metadata only
meta = get_file_metadata("scratchpad://session/file.txt")
print(f"Size: {meta.size} bytes, Lines: {meta.line_count}")

# Read chunk
chunk = read_file_chunk("scratchpad://session/large.log", offset=0, limit=1024)
print(chunk.content.data)
```
